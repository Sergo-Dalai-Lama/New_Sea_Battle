#РАБОТА С КОПИРОВАНИЕМ

Когда копируем объекты, то есть два типа копирования - простое и глубокое. При простом копировании создается копия объекта, но если там есть изменяющиеся значения (Mutable) (к ним относятся например классы с изменяемыми полями, коллекции), то при изменении скопированного объекта изменится и оригинальный, поэтому существует глубокое копирование. Оно тоже бывает с разным синтаксисом. В моем коде при копировании EnumMap несколько сложностей возникло, поэтому распишу тут как это всё работает.

Глубокое копирование это нескольких сложных механизмов: new, копирования коллекций и иногда  clone().

Если писать NameClass copy = original, то копирования вообще не будет, так как обе переменные ссылаются на один объект.

Если сделать NameClass copy - new NameClass(original); и внутри констурктора правильно скопировать поля, то получим другой объект, это уже копирование самого NewClass. Но внутри может быть NameClass original -> mutableValue, тогда copy ->mutableValue, но глубокая копия должна дать newValue.

Обычный класс: copy constructor - самый контролиремый способ:
```class NewClass {

private string name;
private Value value;

public NewClass(string name, Value value){
this.name;
this.value;
}

public NewClass(NewClass other) {
this.name;//скопировать примитив или immutable
this.value = new Value(other.value);//скопировать с созданием нового объекта mutable объект
	}
}
```

Здесь конструкция public NewClass(NewClass other) называется копировальным конструктором. Потом можно писать NewClass copy = new Newclacc(riginal); который можно расшифровывать как "создать новый NewClass, используя существующий NewClass original как источник данных.

List<> не является неизменяемым, а так же имеет вложенные в себя объекты, оторые так же могут быть mutable, поэтому:
this.value = new ArrayList<>(other.value);

У record автоматически создается canonical constructor, поэтому для создания копии можно просто писать NewClass copy = new Newclass(riginal).

Если List<NewClass>, то нужно глубокое копирование и для record, потому что стандартного копирования его не достаточно. Стандартное копирование списка сложных объектов такое:
```
record NewClass (Srting name, List<OtherClass> other) {
public NewClass(NewClass otherObject) {
this(
otherObject.name(),
otherObject.other()
.stream()
.map(OtherClass::new)
.toList()
);
	}
}
```

#Работа с JFrame и JPanel
Когда настраиваем окно JFrame - сначала не известен размер окна и его содержимого. Не известен цвет. Окно не может быть без содержимого и если настраивать параметры
при отсутствующем содержимом, они могут отображаться некорректно. Поэтому необходимо добавить основание JPanel под названием contentPane.
После добавления contentPane надо настроить его через setColor - настройка цвета, setPrefferedSize - настройка предпочтительного размера.
Настройки применяются только после метода pack(), который по сути применит настройки и после этого можно будет центрировать добавленные поверх contentPane объектов.
setLocation объектов работает только если я в них настроил setBounds, в ином случае надо применять setBounds к экземпляру объекта

#Работа с void paint
Когда используем метод paint, то он делает полный цикл отрисовки.
super.paint(g) - сначала рисует paintComponent, потом paintBorder, потом paintChildren - корабли рисуются здесь, и другие объекты-дети тоже
Если я после этого вызываю методы рисования, то они будут рисовать поверх объектов-детей и перекрывать их.
Поэтому лучше рисовать фон panel в методе paintComponent

#Работа с поиском ближайшей точки
Разберем код 
```
private Point findNearestSnapPoint(Point point, int maxDistance) {
        Point nearestPoint = null;
        double minDistance = Double.MAX_VALUE;
        for (Point snapPoint: targetPanel.getPoints()){
            double distance = point.distance(snapPoint);
            if (distance < minDistance) {
                minDistance = distance;
                nearestPoint = snapPoint;
            }
        }
        if (nearestPoint!=null&&minDistance <= maxDistance) {
            return nearestPoint;
        }

        return null;
    }
```
Сначала мы инициализируем ближайшую точку - так как не нашли, то указываем null здесь Point nearestPoint = null;
Потом мы указываем минимальное расстояние которое видели, сначала указываем максимально возможное - Double.MAX_VALUE.
После этого идет перебор всех точек и вычисляется та, до которой расстояние самое маленькое.
Дистанция вычисляется как евклидово расстояние.
На каждой итерации спрашиваем "Ближе ои эта точка, чем уже сохраненная" и если ближе, то сохраняем эту
точку в качестве привязки.
После того как прошли все точки мы сначала проверяем, нашли ли вообще точку, потом смотрим, удовлетворение условию, что
она ближе, чем указанное ограничение дистанции.
